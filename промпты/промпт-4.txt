Создай учебное консольное приложение на Python для генерации PDF-чеков из данных формата CSV или JSON на основе HTML-шаблонов. 
Выполни задачу полностью: создай структуру проекта, все необходимые файлы, тестовые данные и установи зависимости.

1. Структура проекта

Организуй проект в текущей рабочей директории со следующей структурой:


├── data/               # Входные файлы с данными (CSV и JSON)
├── templates/          # HTML-шаблоны чеков
├── output/             # Папка для сохранения готовых PDF (создавать автоматически, если отсутствует)
├── main.py             # Основной исполняемый скрипт
├── requirements.txt    # Список зависимостей (pandas, jinja2, weasyprint)
└── README.md           # Краткая инструкция по запуску и установке системных зависимостей (GTK3 для Windows)


2. Логика работы main.py

1. Поиск файлов:
	• Сканирует директорию data/ и находит все файлы с расширениями .csv и .json.
	• Сканирует директорию templates/ и находит все файлы с расширением .html.
	• Если в какой-то из папок нет подходящих файлов, выводит понятное сообщение на русском языке и корректно завершает работу.
2. Интерактивное консольное меню:
	• Выводит пронумерованный список доступных файлов с данными и просит пользователя выбрать файл по номеру через input() 
          (с проверкой корректности ввода, чтобы программа не падала при вводе букв или несуществующего номера).
	• Выводит пронумерованный список доступных HTML-шаблонов и просит выбрать нужный по номеру.
3. Парсинг данных:
	• Для .csv использует библиотеку pandas (с указанием encoding='utf-8', корректно обрабатывая группировку, если у одного invoice_id несколько позиций товаров).
	• Для .json использует стандартную библиотеку json (с encoding='utf-8').
4. Выбор чека и генерация PDF:
	• Выводит пронумерованный список всех уникальных чеков (по invoice_id, с указанием клиента и даты для наглядности) из выбранного файла.
	• Пользователь выбирает конкретный чек по номеру.
	• Данные выбранного чека подставляются в выбранный HTML-шаблон с помощью шаблонизатора Jinja2.
	• С помощью WeasyPrint генерируется PDF-документ и сохраняется в output/invoice_<invoice_id>.pdf.
5. Кроссплатформенное открытие PDF:
	• После успешного сохранения скрипт автоматически открывает созданный PDF в программе по умолчанию (os.startfile() для Windows, 
          subprocess.run(["open", filepath]) для macOS и xdg-open для Linux).

3. Требования к оформлению, шрифтам и обработке ошибок

• Поддержка кириллицы: В HTML-шаблоне обязательно пропиши CSS-правила для шрифтов с поддержкой кириллицы (font-family: "DejaVu Sans", 
  "Roboto", Arial, sans-serif;) и тег <meta charset="UTF-8">, чтобы русский текст в PDF гарантированно отображался без искажений.
• Защита от ошибок на Windows (WeasyPrint): Оберни импорт и вызов weasyprint в блок try...except OSError. Если на Windows отсутствуют системные 
  библиотеки GTK3 (cannot load library 'gobject-2.0-0'), перехвати ошибку и выведи пользователю понятную подсказку на русском языке о том, как установить GTK3 (например, через winget install tschoonj.GTKForWindows или установщик GTK3 Runtime) и перезапустить терминал.
• Чистый консольный интерфейс: Используй аккуратное форматирование, разделители и понятные подсказки на русском языке на каждом шаге.

4. Тестовые данные (создай их сразу)

Наполни проект готовыми примерами на русском языке, чтобы программу можно было протестировать сразу после запуска:
• data/invoices.json: 3 разных чека с полями invoice_id, date, customer, items (список товаров с названием, количеством и ценой) и total.
• data/invoices.csv: таблица с 2–3 чеками (по несколько строк товаров на один invoice_id), чтобы проверить группировку данных через pandas.
• templates/receipt_standard.html: аккуратный современный шаблон товарного чека в стиле минимализм с таблицей позиций, итоговой суммой, рамками и поддержкой кириллицы.
• templates/receipt_compact.html: второй вариант шаблона (например, в формате узкого кассового чека), чтобы можно было протестировать выбор между разными шаблонами.
